# Ovie v2.3 Module System — API Reference

This document is the complete API reference for the Ovie v2.3 module system. It covers CLI commands, file formats, and the `std::module` and `std::aproko` library APIs.

---

## CLI Commands

### Package Management

#### `ovie init <name>`
Creates a new Ovie package in a new directory.

```bash
ovie init my-app
```

Creates:
- `my-app/src/main.ov` — entry point
- `my-app/ovie.toml` — package manifest
- `my-app/.gitignore`

#### `ovie add <package>`
Adds a dependency to `ovie.toml`.

```bash
ovie add oba                        # add from package registry
ovie add oba --path ./oba           # add local path dependency
ovie add oba --version ">=1.0.0"    # add with version constraint
```

#### `ovie install`
Reads `ovie.toml`, resolves all dependencies, installs them, and generates/updates `ovie.lock`.

```bash
ovie install
```

#### `ovie migrate <file>`
Analyzes a standalone `.ov` file and adds appropriate `import`/`export` statements and generates an `ovie.toml`.

```bash
ovie migrate src/main.ov
ovie migrate --dry-run src/main.ov   # preview changes without writing
```

### Documentation

#### `ovie doc`
Generates HTML, Markdown, and JSON documentation for the current project.

```bash
ovie doc                        # generate docs in docs/output/
ovie doc --format html          # HTML only
ovie doc --format markdown      # Markdown only
ovie doc --format json          # JSON only (for tooling)
ovie doc --output ./my-docs     # custom output directory
```

#### `ovie doc check`
Validates that all exported functions have complete doc comments. Exits with code 1 if any are missing.

```bash
ovie doc check
ovie doc check src/math.ov      # check specific file
```

### Aproko Knowledge Base

#### `ovie aproko query`
Queries the knowledge base for stored analysis results.

```bash
ovie aproko query --category TypeInformation
ovie aproko query --symbol add
ovie aproko query --category CodePattern --pattern-type ErrorHandling
ovie aproko query --module std::math
ovie aproko query --min-confidence 0.8
```

Options:
- `--category` — filter by category: `TypeInformation`, `ReasoningRule`, `CodePattern`, `SecurityIssue`, `PerformanceHint`, `Documentation`
- `--symbol` — filter by symbol name
- `--pattern-type` — filter by pattern type (for CodePattern entries)
- `--module` — filter by module name
- `--min-confidence` — minimum confidence threshold (0.0–1.0)

#### `ovie aproko export`
Exports the entire knowledge base to a JSON file for LLM/tool consumption.

```bash
ovie aproko export                          # exports to .ovie/aproko/export.json
ovie aproko export --output knowledge.json  # custom output path
```

### Book

#### `ovie book serve`
Serves the "Ovie in Southern Kaduna" book locally with hot reloading.

```bash
ovie book serve                 # serves on http://localhost:3000
ovie book serve --port 8080     # custom port
```

#### `ovie book test`
Extracts all code examples from the book chapters and validates they compile and run correctly.

```bash
ovie book test
ovie book test --chapter 3      # test specific chapter
```

## File Formats

### `ovie.toml` — Package Manifest

```toml
[package]
name = "my-app"
version = "1.0.0"
description = "My Ovie application"
authors = ["Your Name <you@example.com>"]
license = "MIT"

[dependencies]
oba = { path = "./oba" }
some-lib = { version = ">=1.2.0, <2.0.0" }
optional-lib = { version = "1.0.0", optional = true }

[dev-dependencies]
test-helpers = { path = "./test-helpers" }

[build]
entry = "src/main.ov"
target = "interpreter"          # interpreter | wasm | llvm
output = "dist/"
```

**Version constraint syntax:**
- `"1.0.0"` — exact version
- `">=1.0.0"` — minimum version
- `">=1.0.0, <2.0.0"` — version range
- `"^1.0.0"` — compatible with 1.x.x

### `ovie.lock` — Lock File

Generated automatically by `ovie install`. Do not edit manually. Commit to version control for reproducible builds.

```toml
# This file is auto-generated by ovie install. Do not edit manually.
version = 1

[[package]]
name = "oba"
version = "0.3.0"
source = "path+./oba"
checksum = "sha256:abc123..."

  [[package.dependencies]]
  name = "std"
  version = "2.3.0"
```

## `std::module` API

### Module Loading

#### `load_module(path: String) -> ModuleResult<Module>`
Loads a module from a file path. Returns cached result if already loaded.

```ovie
use std::module::{load_module};
mut module = load_module("std/math/mod.ov")?;
```

#### `load_module_from_source(path: String, source: String) -> ModuleResult<Module>`
Loads a module from an in-memory source string (used by compiler integration).

#### `load_dependencies(module: Module) -> ModuleResult<Vec<Module>>`
Recursively loads all dependencies of a module in dependency order.

#### `is_loaded(path: String) -> bool`
Returns true if the module at `path` is already in the global registry.

#### `get_module(path: String) -> Option<Module>`
Returns a loaded module by path, or None if not loaded.

### Path Resolution

#### `resolve(module_path: String, config: ResolverConfig) -> ModuleResult<ResolvedModule>`
Resolves a module path like `std::math` to a file path like `std/math/mod.ov`.

```ovie
use std::module::{resolve, default_config};
mut config = default_config();
mut resolved = resolve("std::math", config)?;
seeAm(resolved.file_path);  // "std/math/mod.ov"
```

#### `default_config() -> ResolverConfig`
Returns a ResolverConfig with standard search paths (current dir → packages → stdlib).

#### `path_to_file(module_path: String) -> String`
Converts `std::math` to `std/math/mod.ov` without searching the filesystem.

### Dependency Graph

#### `new_graph() -> DependencyGraph`
Creates an empty dependency graph.

#### `add_module(graph: &mut DependencyGraph, path: String)`
Adds a module node to the graph.

#### `add_dependency(graph: &mut DependencyGraph, from: String, to: String)`
Adds a dependency edge: `from` imports `to`.

#### `topological_sort(graph: &DependencyGraph) -> Result<Vec<String>, CircularDependency>`
Returns modules in compilation order (dependencies before dependents). Returns error if cycles exist.

#### `detect_cycles(graph: &DependencyGraph) -> Option<CircularDependency>`
Returns the first cycle found, or None if the graph is acyclic.

#### `get_transitive_deps(graph: &DependencyGraph, path: &String) -> Vec<String>`
Returns all transitive dependencies of a module (no duplicates).

#### `build_graph_fast(pairs: Vec<(String, Vec<String>)>) -> DependencyGraph`
Builds a complete dependency graph in O(n) from a list of (module, deps) pairs.

### Caching

#### `new_cache(config: CacheConfig) -> ModuleCache`
Creates a new module cache.

#### `default_cache_config(compiler_version: String) -> CacheConfig`
Returns a CacheConfig using `.ovie/cache/` as the cache directory.

#### `is_cache_valid(cache, path, src_hash, deps_hash, time) -> bool`
Returns true if the cached entry for `path` is still valid.

#### `cache_module(cache, path, src_hash, deps_hash, artifact, time) -> ModuleResult<String>`
Stores a compiled artifact in the cache. Returns the artifact path.

#### `get_cached(cache, path, src_hash, deps_hash) -> Option<String>`
Returns the cached artifact content if valid, or None on cache miss.

#### `invalidate(cache: &mut ModuleCache, path: &String)`
Removes a single module from the cache.

#### `clear_cache(cache: &mut ModuleCache)`
Removes all entries from the cache.

### Performance Utilities

#### `new_cache_index(max_hot: usize) -> CacheIndex`
Creates an LRU hot index for O(1) cache validity checks.

#### `hot_check(index, path, src_hash, deps_hash) -> "valid" | "invalid" | "miss"`
Checks the hot index without disk I/O.

#### `build_graph_fast(pairs) -> DependencyGraph`
O(n) graph construction from a pre-computed dependency list.

#### `prewarm_stdlib(cache, index, std_root, version) -> u32`
Pre-warms the hot index with all standard library modules. Returns count of modules warmed.

## `std::aproko` API

### Storage

#### `store_entry(entry: KnowledgeEntry)`
Stores or updates a knowledge entry. If an entry with the same ID exists, increments its version.

```ovie
use std::aproko::{store_entry, kb_entry_new};
mut entry = kb_entry_new("add-type-info", "TypeInformation", "{\"return\": \"Number\"}");
entry.symbol_name = "add";
entry.module_name = "std::math";
store_entry(entry);
```

#### `update_entry(id: String, new_content: String) -> Boolean`
Updates the content of an existing entry by ID. Returns false if not found.

### Querying

#### `kb_query(q: KnowledgeQuery) -> KBResult`
Queries the knowledge base with filter criteria.

```ovie
use std::aproko::{kb_query, KnowledgeQuery};
mut q = KnowledgeQuery {
    category: "TypeInformation",
    symbol_name: "add",
    pattern_type: "",
    module_name: "",
    min_confidence: 0.0,
};
mut result = kb_query(q);
```

#### `get_reasoning_rules(pattern_type: String) -> Array`
Returns all reasoning rule entries, optionally filtered by pattern type.

#### `get_type_info(symbol_name: String) -> Array`
Returns type information entries for a specific symbol.

#### `get_patterns(pattern_type: String) -> Array`
Returns code pattern entries filtered by pattern type.

### Export

#### `export_json(output_path: String)`
Exports the entire knowledge base to a JSON file formatted for LLM consumption.

## Migration Guide

See [docs/migration-v2.2-to-v2.3-modules.md](migration-v2.2-to-v2.3-modules.md) for the complete guide on migrating from v2.2 standalone files to the v2.3 module system.

**Quick summary:** No changes required. Standalone `.ov` files continue to work. The module system is opt-in — add `use`/`export` statements when you're ready to modularize.
